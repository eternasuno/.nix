# Tailwind CSS Rules

Apply when implementing or reviewing Tailwind markup, utility classes, responsive variants, or configuration, with or without a component library. Preserve the installed version; styling work does not authorize adopting or upgrading Tailwind.

## Utilities and component boundaries

- Reuse component-library styles where available and use Tailwind utilities for remaining expressible presentation; raw CSS is reserved for demonstrated unsupported requirements, framework configuration, and theme tokens. Do not hide complexity in `@apply`, giant class constants, or sprawling descendant selectors. Simplify utilities and extract cohesive reusable UI components.
- Prefer built-in utilities and spacing, typography, radius, width, and breakpoint scales over custom equivalents or near-equivalent arbitrary values. Accept minor visual differences rather than recreating built-in styles unless an explicit requirement, accessibility, or necessary interaction requires the difference. When a component library supplies the required style or variant, use it rather than reconstructing it with utilities.
- Express responsive presentation with utility variants. Use built-in breakpoint variants unless behavior requires a distinct threshold.
- Keep utilities attached to the element or cohesive component that owns the presentation. Runtime values such as measured dimensions and generated anchor names may use inline CSS variables with static utilities; do not construct class names that the compiler cannot discover.

## Utility reuse and overrides

- Keep shared utility styles in the semantic component that owns the visual contract rather than copying utility strings across consumers.
- Remove superseded utilities and conflicting classes during migration. Use important utilities only when ordinary utilities or scoped overrides cannot meet the requirement after inspecting the cascade.

## Configuration and verification

- Use CSS-first configuration for new Tailwind 4 setups. Migrate existing JavaScript configuration only in an explicitly authorized configuration migration; do not expand a local UI edit into a build migration.
- Verify required utilities are generated by the installed compiler, especially arbitrary values and variants. In Tailwind 4, register custom utility-producing tokens in the appropriate `@theme` namespace; a variable declared only in a component-library theme does not itself generate a Tailwind utility. Compiler success does not establish browser rendering or interaction correctness.

Done when expressible styles use utilities, component boundaries remain meaningful, necessary exceptions are explained, and verification reflects the actual affected states.
