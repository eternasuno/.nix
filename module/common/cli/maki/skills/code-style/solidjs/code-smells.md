# SolidJS 2.0 Code Smells

Apply when reviewing or refactoring SolidJS 2.0 components, reactivity, UI state, forms, and data flow. Proactively read `node_modules/solid-js/CHEATSHEET.md`, `node_modules/solid-js/skills/solid-2.0/SKILL.md`, and `node_modules/solid-js/skills/reactivity-diagnostics/SKILL.md` when present (plus `node_modules/@solidjs/diagnostics/skills/agent-loops/SKILL.md` for reactive verification and `node_modules/@solidjs/web/skills/server-components/SKILL.md` for `"use server"` components). Combine with [Web platform code smells](../web-platform/code-smells.md) for browser behavior.

- **Legacy or React patterns:** `solid-js/store`, `solid-js/web`, `jsxImportSource: "solid-js"`, `createResource`, `Suspense`, `SuspenseList`, `ErrorBoundary`, `<Index>`, `mergeProps`, `splitProps`, `unwrap`, `produce`, `onMount`, `batch`, `Context.Provider`, `classList`, `use:` directives, or React re-render assumptions.
- **Untracked reads and setup snapshots:** reactive signals, memos, stores, or props read at the top of a component body or flow callback (`<For>`, `<Show>`, `<Match>`), destructured props (`function Comp({ name })`), plain prop spreads, passing accessors where JSX props expect values (or eager values where hooks expect accessors), conditional event handler bindings (`onClick={cond() ? a : b}`), or `untrack` used to silence `[STRICT_READ_UNTRACKED]`.
- **Duplicate or overconsolidated state:** synchronized signals/effects, mirrored DOM state, or unrelated fields grouped to reduce signal count. Derive scalars with derived accessors or `createMemo` and collections with `createProjection`, preserving independent ownership.
- **Invalid effect shapes, writes, or timing assumptions:** single-argument `createEffect(fn)`, writes to signals or stores inside a `createMemo`, an effect's `compute` function, or a component body, missing cleanup returned from `createEffect`'s apply phase or `onSettled`, reads after `await`, stale-result checks mistaken for request cancellation, missing `flush()` before synchronous post-write reads/assertions, or calling `flush()` inside an `action`.
- **Direct store mutation or broken reconciliation:** mutating an exposed store proxy directly instead of using draft setters (`setStore(s => { ... })`), replacing arrays of fresh objects without `createProjection` `{ key }` or `reconcile`, or mutating `snapshot` copies expecting reactive updates.
- **Premature ref-based DOM integration:** ref-time measurement or initialization requiring dynamic attributes, connected layout, or uninitialized children instead of `onSettled`; for virtualized lists, verify index lookup, measured row heights, resize tracking, and reuse after scrolling before changing estimates or clipping overflow.
- **List identity or conditional rendering bugs:** `.map()` used for reactive list rendering, wrong `<For>` keyed vs. `keyed={false}` or `<Repeat>` choice, or non-reactive branching.
- **Async, boundary, and mutation anti-patterns:** manual loading/error signal mirrors instead of async `createMemo` / `createStore(fn)` / `createProjection` with `<Loading>` and `<Errored>`, forgetting that `<Errored>` fallback receives an error accessor (`err()`), missing `on={deps}` when `<Loading>` should re-arm, or relying on subtree `<Errored>` for event-handler or detached async errors.
- **Universal fixed-form machinery:** configuration-, schema-, or field-descriptor-generated or mode-switched fixed business forms are noncompliant and must be rewritten as explicit composed forms, even when they are an existing convention.
- **Unnecessary controlled forms and DOM property hazards:** per-field value/touched/invalid signal mirrors when values do not drive live reactive consumers, bypassing router `formAction` contracts, or `<progress value={undefined}>` instead of omitting `value` for indeterminate progress.
- **Router cache or mutation mistakes:** mismatched `@solidjs/router` query keys/arguments, blocking preload awaits instead of `<Loading>` boundaries, or bypassing `formAction`/revalidation contracts.
- **SSR or security boundary violations:** browser APIs (`window`, `document`, `localStorage`) at module scope or render time instead of `onSettled`, effect apply functions, `!isServer`, or `clientOnly`; module-scope mutable signals/stores on the server; leaked `render` disposers; unsafe `innerHTML`; exposed client secrets; or missing server-side validation/auth inside `"use server"` functions.
- **Missing diagnostics/lint verification or unjustified optimization:** suppressed or ignored bracketed diagnostic codes, skipped `eslint-plugin-solid/configs/v2` or `@solidjs/diagnostics` checks, unnamed reactive scopes in non-trivial flows, or unmeasured splitting, virtualization, or memoization.
